# LiveCrime Site — Roadmap

## 1. Цель проекта

Создать небольшой статический сайт с полезными карточками криминальных
событий. Сайт должен дополнять Telegram-канал, помогать читателям находить
проверенную информацию и приводить аудиторию в канал.

Первая версия размещается бесплатно на GitHub Pages. После проверки MVP к
этому же проекту подключается собственный домен без переписывания сайта.

## 2. Неприкосновенные ограничения

- Существующий LiveCrime-автопостер остаётся главным независимым процессом.
- Не меняются сбор новостей, фильтрация, score, дедупликация, формат поста,
  отправка в Telegram и `storage/published.json`.
- Ошибка генерации, сборки или публикации сайта не должна мешать Telegram.
- Сайт не отправляет посты в Telegram и не инициирует повторную публикацию.
- MAX не входит в проект: публикации попадают туда из Telegram через уже
  настроенный внешний сервис репостов.
- Первая версия использует только бесплатные инструменты и GitHub Pages.
- Лучше не создать страницу, чем опубликовать слабую или недостоверную
  карточку.

## 3. Что считается полезной карточкой

Карточка события — не копия текста СМИ и не короткий SEO-пересказ. Она должна
иметь самостоятельную справочную ценность.

Минимально полезная карточка содержит:

- понятный заголовок;
- дату события или честное указание, что она уточняется;
- место события;
- краткое нейтральное описание подтверждённых фактов;
- текущий статус события или дела;
- дату создания и последнего обновления карточки;
- ссылки на использованные источники;
- хронологию существенных обновлений;
- ссылку на Telegram-канал;
- связанные материалы, если они действительно относятся к событию.

Нельзя выдавать подозрение или обвинение за установленную вину. Полный текст
чужой статьи на сайт не переносится.

## 4. Общая архитектура

```text
Существующий LiveCrime
    |
    | успешная Telegram-публикация и обновление published.json
    v
Отдельный генератор сайта
    |
    | проверка новых записей и качества данных
    v
Markdown-карточки событий
    |
    v
Astro build
    |
    v
GitHub Pages
```

Генератор сайта работает только как потребитель уже подтверждённого состояния.
У него будет собственный файл состояния, поэтому повторный запуск не создаст
вторую карточку.

## 5. Предполагаемая структура папки

```text
site/
├── ROADMAP.md
├── README.md
├── package.json
├── astro.config.mjs
├── public/
│   ├── robots.txt
│   └── favicon.svg
├── src/
│   ├── content/
│   │   ├── config.ts
│   │   └── events/
│   ├── layouts/
│   ├── pages/
│   ├── components/
│   └── styles/
└── tests/
```

Эта структура будет создаваться постепенно. На текущем этапе фиксируется
только план, без реализации сайта.

## 6. Модель события

Для каждой карточки нужен постоянный `event_id`, не зависящий от изменяемого
заголовка.

Ориентировочные поля Markdown frontmatter:

```yaml
event_id: ""
title: ""
slug: ""
event_date: ""
location:
  country: "Россия"
  region: ""
  locality: ""
status: "reported"
created_at: ""
updated_at: ""
topics: []
sources: []
updates: []
related_events: []
telegram_channel_url: ""
draft: true
```

Точный контракт будет утверждён до написания генератора и покрыт тестами.

## 8. Что не входит в MVP

- Публикация в MAX или интеграция с MAX API.
- Изменение Telegram-постов или Telegram publisher-а.
- Платный сервер, база данных или CMS.
- Массовый автоматический импорт всех старых публикаций.
- Автоматическая публикация страницы при недостатке данных.
- Копирование полных текстов и изображений СМИ.
- Генерация большого числа страниц по ключевым словам ради SEO.
- Комментарии пользователей, регистрация и личные кабинеты.

## 9. Обязательные проверки безопасности

Перед каждым релизом сайта необходимо подтвердить:

- существующие Python-тесты автопостера не получили регрессий;
- файлы Telegram publisher-а и его конфигурация не изменились;
- `storage/published.json` не изменяется генератором сайта;
- сайт не знает Telegram bot token и не вызывает Telegram API;
- повторный запуск не создаёт вторую карточку;
- ошибка сети или Astro build не влияет на Telegram;
- в репозиторий не попали секреты, временные файлы и чужие полные тексты;
- индексируются только карточки, прошедшие quality gate.

## 10. Критерии готовности MVP

MVP считается готовым, когда:

1. Существующий автопостер работает без изменения поведения.
2. Новая подтверждённая публикация обнаруживается отдельным генератором.
3. Для подходящего события создаётся ровно одна Markdown-карточка.
4. Неполное событие остаётся черновиком или не создаётся.
5. Astro успешно собирает главную и страницы событий.
6. GitHub Pages автоматически публикует проверенную сборку.
7. Страница содержит дату, место, статус, источники и ссылку на Telegram.
8. Повторный запуск и сбой site workflow не создают Telegram-дубликаты.
9. Сайт готов к последующему подключению собственного домена.

## 11. Порядок ближайших работ

Следующий шаг после утверждения этого roadmap — создать только базовый каркас
Astro и одну демонстрационную карточку. Подключение к реальному
`published.json` выполняется позже, после проверки структуры и дизайна на
тестовых данных.
