# «По факту» — сайт медиахаба

Отдельный статический сайт будущего тематического медиахаба «По факту». Первый
пилотный раздел — «Криминал». После проверки процесса к общей системе можно
добавить Roblox, кошек, MMA, автомобили и звёзд.

Сайт не публикует сообщения в Telegram или MAX и не изменяет состояние
криминального автопостера. В публичном реестре находятся только прошедшие
отдельную редакционную проверку материалы.

Отдельный безопасный импортёр читает только подтверждённые записи из
`storage/published.json` и помещает новые материалы в очередь проверки внутри
`site/data/inbox/`. Кандидат из очереди не становится страницей автоматически.

## Основные страницы

- `/` — главная страница хаба;
- `/crime/` — реестр криминальных событий;
- `/crime/<event-id>/` — постоянная карточка события;
- `/about/` — понятное описание проекта для читателя.

## Локальный запуск

```bash
npm install
npm run dev
```

## Очередь новых публикаций

При первом подключении нужно один раз зафиксировать текущую границу истории,
чтобы не импортировать весь старый архив:

```bash
python3 -m generator.import_published --initialize
```

После этого проверка новых подтверждённых публикаций запускается из папки
`site/` командой:

```bash
python3 -m generator.import_published
```

За один запуск в очередь попадает не больше одной записи. Импортёр не получает
тексты статей из сети, не создаёт индексируемую страницу и никогда не изменяет
историю автопостера. JSON-файлы реальных кандидатов и редакционных заметок
исключены из Git до прохождения проверки качества.

Workflow `Site Editorial Intake` выполняет ту же операцию ежедневно и допускает
ручной запуск. Для криминального пилота он пропускает одиночные убийства и
берёт только заголовки, где явно указаны минимум две жертвы убийства. Затем он
сохраняет один кандидат как закрытый GitHub Actions artifact на 14 дней и
коммитит только собственную границу чтения
`site/data/generator-state.json`. Публичная страница из кандидата автоматически
не создаётся.

Сайт не создаёт автоматические страницы городов, тегов и ключевых слов. Новый
публичный маршрут добавляется только вместе с самостоятельным полезным
содержанием; это правило проверяется тестами при каждой публикации.

Проверка типов и production-сборка:

```bash
npm run build
```

## Временный адрес GitHub Pages

Для этого репозитория production-сборка использует временный адрес:

```text
https://teadrunkerhard777.github.io/LiveCrime/
```

Локально такую же структуру адресов можно проверить командой:

```bash
SITE_URL=https://teadrunkerhard777.github.io \
BASE_PATH=/LiveCrime npm run build
```

Отдельный `.github/workflows/site.yml` собирает только папку `site/`. Он не
запускает автопостер, не получает Telegram secrets и не изменяет
`storage/published.json`.

Чтобы выполнить первое развёртывание, после отправки файлов в GitHub необходимо
один раз выбрать **GitHub Actions** как источник публикации в настройках Pages
репозитория. Подключение собственного домена позднее не потребует переписывать
контент.

Продуктовые решения зафиксированы в [PRODUCT.md](./PRODUCT.md), а подробный план
находится в [ROADMAP.md](./ROADMAP.md).
